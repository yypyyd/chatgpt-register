### 实现

协议链路已按官网验证码页 `clientLoader` 的顺序补齐：

1. 从 `/api/accounts/client_auth_session_dump` 读取当前 auth session。
2. 仅在 `passwordless_email_otp_send_pending=true`、session ID 和邮箱非空，且验证模式为未设置、`passwordless_login` 或 `passwordless_signup` 时继续。
3. 为 `authorize_continue` flow 获取官方 Sentinel token 与 Session Observer token。
4. 通过 client auth session cache 再次复核 session ID、邮箱、验证模式和 pending 状态；身份发生变化立即终止。
5. POST `/api/accounts/passwordless/send-otp`，只把 HTTP 2xx 且没有 auth JSON error 视为接受。
6. 以请求开始时间的 UTC 整秒作为第一次邮箱轮询起点，避免 Graph 秒级时间精度遗漏同秒到达邮件。

同时完成以下配套修改：

- `/api/accounts/passwordless/send-otp` 使用 `authorize_continue` Sentinel flow。
- pending=false 或验证模式不匹配时不重复发信。
- 创建密码路径跳转到验证码页后保存最新页面 HTML，避免继续使用旧页面快照。
- 原有 `/email-otp/resend` 仅保留为首次发码已执行后仍未投递的恢复手段，并继续与错误验证码恢复共享一次重发预算。
- 首次发码失败会立即返回精确错误，不会先空等邮箱轮询超时。

首次现场版本在 Sentinel 签发前后各强制请求了一次 session dump；第二次 GET 命中 Cloudflare challenge。官网的 session helper 会命中同一份 client auth session cache，并不会在 checksum 未变化时强制第二次网络 dump。实现改为相同的缓存复核后，challenge 消失；身份字段及 pending 状态的二次一致性检查仍然保留。
